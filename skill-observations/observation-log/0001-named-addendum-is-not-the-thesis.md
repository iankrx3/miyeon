**Issue:** User asked for a 500-character AI-utilization summary of the whole project and to also include a removed Gemini web-grounding feature. The first draft made grounding the entire piece (model, opt-in click, proxy, fail-silent, sources) and treated itinerary matching as a one-line afterthought. The user then asked not to concentrate only on that feature and to cover how AI was used across the project.

**Suggested improvement:** When a user names one extra item to include in a broader summary, treat it as a must-keep constraint occupying a proportional share — not as the thesis. Inventory the rest of the scope first, then slot the named item in.

**Principle:** A named addendum is a constraint, not the thesis. Include it, then keep it proportional to the rest of what was asked.
